# Evidence to experiment

BLUF: Turn traceable evidence into a decision or one small test. Do not turn an idea into a commitment.

Installed workflow. Verify the selected mode against its output contract.

## Inputs and routing
Use the question or raw idea, scope, audience, existing work, and allowed sources.
Choose one mode: research, idea, sweep, or claims audit. Run only the selected mode.
For private source conversion, use source-to-study-pack instead.

## Shared steps
1. State the decision, time window, exclusions, and acceptance test. Search existing work before proposing a duplicate.
2. Keep the raw idea unchanged. Label additions as proposals.
3. Prefer primary sources and firsthand reports. Record links and retrieval dates. Verify decision-critical values at the source. A snippet is not verification.
4. Keep facts, estimates, assumptions, and experiments separate. Reviews, badges, and engagement are proxies, not verified outcomes.
5. Record contradictions and missing evidence. Never fill a gap with a plausible value.

## Modes
- Research: compare audience problems, formats, structure, onboarding, complaints, effort, differentiation, testability, and dependency risk. Rank at most three options. Borrow mechanisms, not another creator's text, images, files, or proprietary logic.
- Idea: connect to existing notes and past attempts. Show tensions with current priorities. Define one experiment with an output, go or stop result, and review date. An idea may remain a question.
- Sweep: use only an explicitly requested scope or an authorized routine. Keep candidates with a detailed firsthand build report or multiple independent confirmations. Dedupe against the index. File at most five with proof grades. Keep the working collection private.
- Claims audit: list each factual claim, implied confidence, source, correct label, contradiction, and proposed fix. Do not alter the audited source.

## Evidence labels
VERIFIED means inspected supporting evidence with a locator.
VERIFIED HIGH needs two independent supporting sources.
LIKELY is reasoned or secondhand, not verified.
UNKNOWN lacks a check. CONFLICT means sources disagree.
A generic definition is not evidence for a specific implementation or result.

## Output and finish
Lead with the answer. Include the evidence table, ranked options or experiment, gaps, and one next action.
For a build, add files, features, exclusions, and test cases.
If revisiting a topic, propose updating one existing report and evidence folder. Create an interactive view only when it improves the decision and the user requested that deliverable.
Check that every value on the view agrees with the evidence.
Nothing here authorizes an outside action.

## Common mistakes
A popular example is not proof of demand. A requested feature is not a built feature. A confident explanation is not verified execution.
